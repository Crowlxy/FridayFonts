# Friday Sans 3.1.0 検証記録

## 入力の訂正

以前の試作・比較には `sans-v3.0/FridaySans-3.0.zip` を使用したが、これは内部版 **3.000** だった。3.002 を基にしたという以前の説明は誤り。3.1.0 では `sans-v3.002/FridaySans-3.002.zip` を取得し、TTF 全10書体の SHA-256 が `releases/sans-3.0/font-manifest.json` と一致することを確認した。Regular の SHA-256 は `22c514d6214bd777cb6d9274eb02787998c891af154b178f2200733084263e66`。

以前指摘した `共唄戯罘疼魃趯纚鱺斌昆槨緝襄襲譏輯錻驪` の Light の輪郭破損は、正しい 3.002 では修正済みである。無印・UI の19字を 3.000、3.002、Noto Light と並べて確認し、3.1.0 でも 3.002 の同じ輪郭点を維持した。比較画像は `work/sans-3002-input/compare-light.png`。

## 3.1.0 の変更と検証

- 10書体について、平らな欧文・数字の足を0にそろえ、丸い `0 O 6 8 9 o c e s` の輪郭を維持。補正の対象は「基準線上に水平な辺がある足」だけです。そのため `t` 系は、足の辺が基準線の少し上にある Light・Regular・UI の同ウェイトでは補正され、Medium〜Bold では曲線の足がオーバーシュートしたまま（UI Bold の `t` は yMin −36）で、補正されません。曲線の足を丸字と同じく扱う意図的な結果です。
- 文章の U+2026 は Latin・英語文脈では下寄り、日本語文脈では中央寄りとし、数式の U+22EF は中央寄りを保持。単独の文字で言語・文字種を識別できない場合は中央寄り。言語別、縦書き、既存機能の組版を検査。
- ⓪、➀〜➈、⊕⊖⊗⊘、⨸、私用文字と `ss05` の囲み字形など計61グリフ／書体を字幅内に収めた。輪郭点・輪郭構成を保持し、字幅と位置を修正。
- UI 書体の ①〜⑳・Ⓐ〜ⓩ は、3.002 で円が字幅の中心より左に約27単位ずれていた（余白 32/87 など）ため、⓪・➀〜➈ と同じく字幅の中央に置き直した。直径・輪郭は変えていない。
- `⸺`・`⸻` は同書体の `—` を基に、各2倍・3倍の字幅へ延長した。線の上下位置と太さは `—` と同じ。縦組み原点は従来を維持。
- 対象外の全グリフの glyf データと字幅・縦メトリクス、GPOS・GDEF の一致を10書体で検証。版表示は `Version 3.100`（製品版 3.1.0）。
- 12・15・24 pxの丸付き字形描画と、64 pxで各字形の丸の内側が残ることを検査。4,400組版ケースを比較し、意図した囲み字形のメトリクス変更以外に差はなかった。TTFの英語・日本語・縦書きの三点リーダーも検査。
- 変更前後のサンプル画像は `work/sans-3.1.0/changes.png`。

## 全ウェイト比較

各書体について Noto Sans JP の同名ウェイト、ヒラギノ角ゴ W2/W3/W4/W5/W6 と共通する文字を、160 px・ヒントなしで一文字ずつ比較した。Noto 13,027文字とヒラギノ 12,376文字、10書体で計254,030組。いずれも共通文字で片方だけが空になる例はなかった。正規化した形状の差、許容幅を設けた局所インク差、フォント単位の輪郭範囲と字幅を別々に記録。結果は `work/sans-3.1.0/audit/part1/`〜`part4/` の20 CSV。

3.1.0 の Regular には15,234コードポイントがあり、制御・私用文字等を除く14,485文字のうち、1,254文字は両参照フォントにないため直接比較できない。全字を全ウェイトで人手で目視したわけではなく、自動比較で拾えない細かな欠けや実機固有の表示差は残り得る。ファミリー名は旧版と同じで、インストール時に競合する可能性がある。
