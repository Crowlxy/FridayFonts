# Friday Mono 5.0 / 2026-10-08

日本語版（Friday Mono JP・Friday Mono Plain JP）の配布を終え、欧文だけのFriday Monoを他の等幅書体と並べて測り直しました。
見つかった劣化をすべて直した版です。
大文字・小文字の高さの比も、SF Monoに合わせました。

- 5つの太さ（Light / Regular / Medium / SemiBold / Bold）と各Italic、計10 TTF・10 WOFF2
- 1,062字。英数字は半角600、行の高さは1.28em（4.93と同じ）
- 大文字・小文字の高さの比をSF Monoに合わせました（キャップ高 / x-height = 1.333、小文字の上端 / キャップ高 = 1.047）
- 数字を大文字と同じ高さにそろえ、4.93の派生ウェイトにあった字形の欠陥（白抜きのアキュート、切れた ogonek・チルダ、Light の Ђ・℮）を直しました

比較したのは次の6書体です。

- Cascadia Mono 2102.025
- Consolas 7.01
- Geist Mono 1.701
- Paper Mono 1.000
- Fragment Mono 1.011
- Roboto Mono 3.001

## 4.93からの変更

### 1. 丸い字が大きく見える問題（C・O・G・S・o・c・e・s）

4.93では、丸い字が平らな字（H・x）より1〜2px高く描かれていました。

- 発生範囲：ほぼすべての太さ・サイズ
- 例：Regularの13〜15pxでは、CがHより2px高い

Windows GDIで9〜32pxを測ると、4.93は10スタイルすべてでずれていました。
同じ測り方で、Cascadia Monoのずれは0です。

**原因**：4.9xの欧文ビルドで、丸い字の上下の端が曲線ではなく短い折れ線になっていました。

- 例：Oの上端は `(359,740)(359,740)(300,745)(241,740)(241,740)`
- 1スタイルあたり179〜492か所
- 重複した点は2,500〜11,700個

ヒント付け（ttfautohint）はこの部分を「平らな字」と判定します。そのため大文字の基準の高さが、Hの737ではなくOの745になっていました。

**修正**（`scripts/mono50/outline_repair.py`）

- 端の両側の弧を1本の2次曲線にまとめ、端の点に水平の接線を付けました
- 重複した点を整理しました
- ヒントは欧文だけのフォントとして付け直しました
- この修正だけでは、外接矩形と字幅は1字も変わりません。高さを変えていない409字で、面積比の差は1%未満（平均0.05〜0.09%）です

5.0の基準の高さ（Regular、6の高さ変更後）：

| | 平らな字 | 丸い字 |
|---|---:|---:|
| 大文字 | 696 | 703 |
| 小文字 | 522 | 530 |
| ベースライン | −2 | −9（大文字）／ −10（小文字） |

**結果**：丸い字と平らな字の高さの差は、9〜32pxで0pxです（10スタイルとも）。

- 測り方：FreeTypeと、Windows GDI（ClearType品質）
- 見本：`reports/proof-round-letters.png`
- GDIの数値：`reports/gdi-heights.json`

### 2. 行の中で文字が上に寄っていた

4.92で二重下線を直すために、下側だけを広げていました（上880／下−400）。
そのため、行の中心がキャップ高の中心より128 units下にありました。比較した6書体は、ほぼ0か、上下に数十units以内です。

5.0では、行の高さ1.28emを保ったまま上968／下−312に配分し直しました。6で大文字を低くしたので、ずれはさらに小さくなっています。

| | 上 / 下 | 行の高さ | 行の中心−キャップ高の中心 |
|---|---|---:|---:|
| 4.93 | 880 / −400 | 1.280em | −128 |
| **5.0** | **968 / −312** | **1.280em** | **−20** |
| Cascadia Mono | 928 / −234 | 1.162em | 0 |
| Geist Mono | 1005 / −295 | 1.300em | 0 |
| Consolas | 743 / −257（+行間171） | 1.171em | −76 |
| Roboto Mono | 1048 / −271 | 1.319em | +33 |

−312は、Windows Terminalの二重下線が分離する最小の下側の値です。

- 条件：8〜24pt × 96/120/144/192dpi の68条件すべて
- 計算方法：4.92と同じ式
- 下線の位置・太さ：−120 / 60のまま

見本：`reports/proof-line-box.png`

### 3. 罫線・ブロック要素が行とずれていた

- 罫線・ブロック160字が、Iosevkaの行枠（−285〜965）のままで、Friday Monoの行枠（−400〜880）と合っていませんでした。エディタでは縦の罫線がつながらず、ブロックが上にずれていました。
- Lightの横線46字は、左右の端が9〜591で止まっていて、文字の境目で途切れていました。
- SemiBoldの横線は、−7〜607とセルの外へはみ出していました。

5.0では、160字すべてを新しい行枠（−312〜968）に合わせ、セルの端を0 / 600にそろえました。
罫線とブロックをセルいっぱいに並べたとき、すき間がないことを9〜24pxで確認しています。

### 4. 収録文字

6書体のうち2書体以上が収録する文字を残す、という基準で見直しました。
例外として、ASCII・Latin-1・罫線・ブロックは票数にかかわらず残します。
各文字の票数と参照した書体のハッシュは、`reports/coverage.json` にあります。

**削除した68字**（1書体以下しか収録していない文字）

| 種類 | 文字 |
|---|---|
| ピンインの声調付き文字 | Ǐ〜ǜ |
| 下点・下線付き文字 | Ḍ Ṃ Ṇ Ṛ Ṭ Ẓ など |
| その他 | Ǹ ǹ、Ԥ ԥ、U+0324、U+032E、‒、⁽ ⁾、⅖〜⅚ |

**文字コードを割り当てた20字**：Ǩ ǰ Ȟ Ȳ Ѷ Ӛ Ӫ Ӭ Ḱ Ṑ Ṓ と、その小文字。
字形はあったのに、4.93では文字コードが割り当てられていませんでした。

**追加した22字**（2〜4票）。既存の▲・□・•・!・’・_ から作っています。

| 種類 | 文字 |
|---|---|
| 三角形 | ▶ ◀ ▴ ▾ ▸ ◂ △ ▽ ▷ ◁ ▵ ▿ ▹ ◃ ► ◄ |
| 菱形・丸 | ◆ ◇ ◦ |
| 記号 | ‼ ‛ ‗ |

**作り直した2字**：▲ ▼。Light・SemiBoldでは上下の位置が8 units食い違っていたので、同じ中心にそろえました。

**見送ったもの**：点字・Powerline・❯ ❮ は、6書体中1書体以下しか収録していないため追加していません。
Windows TerminalとVS Codeのターミナルは、罫線・ブロック・Powerlineの三角を自前で描きます。

### 5. GDIでの行の高さ

usWinAscent / usWinDescentが日本語版の値（1324 / 602）のままだったため、GDIを使うアプリでは行の高さが1.93emになっていました。
5.0では、ラテン・ギリシャ・キリル文字と罫線が収まる値（1000 / 331）にし、全ウェイトで同じ値にしました。

usWinAscentは、行の上端（968）より32 units以上高くしてあります。ttfautohintのWindows互換モードはusWinAscentの位置にゾーンを作ります。そのため、968に近すぎると（989で確認）、罫線の縦線が9〜23pxで高さ0につぶれます。

| | GDIの行の高さ |
|---|---:|
| 4.93 | 1.93em |
| **5.0** | **1.33em** |
| Cascadia Mono | 1.32em |
| Roboto Mono | 1.32em |

ベトナム語の重ねアクセント付き大文字とǺは、GDIのアプリに限り上端が欠けることがあります。比較した書体も同じです。

### 6. 大文字・小文字の高さをSF Monoの比率に合わせた

4.93は、Iosevkaの比率（キャップ高737 / x-height 522 = 1.41、数字745）のままでした。大文字が小文字に対して大きく見えます。
SF Monoは1.3325です。比較した6書体も1.30〜1.39で、Friday Monoだけが外れていました。

x-height（522）は変えず、キャップ高と小文字の上端を下げました（`scripts/mono50/heights.py`）。

| Regular | x-height | キャップ高 | 数字 | 小文字の上端（l・d） | キャップ高 / x | 上端 / キャップ高 |
|---|---:|---:|---:|---:|---:|---:|
| 4.93 | 522 | 737 | 745 | 772（ł・ľ・ħ・ß などは737） | 1.412 | 1.047 |
| **5.0** | **522** | **696** | **696（丸い端は703）** | **729（すべて）** | **1.333** | **1.047** |
| SF Mono（実測） | 529 | 705 | — | 738 | 1.3325 | 1.047 |

- **対象**：大文字・数字・キャップ高の記号（! ? % & # @ $ ¶ № ‰、通貨、分数）を、ベースラインを基準に縮めました。
  - アクセントは字と一緒に下げ、字との間隔は保っています。
  - ベースラインより下のアクセント（下点など）は動かしていません。
- **上に伸びる小文字**：x-heightより上だけを縮め、l・ł・ľ・ß・β・б などの上端を729にそろえました。
  - 4.93では l の 772 と ł の 737 のように、上端が2種類ありました。
  - t の仲間は l と同じ比率で縮めています。
- **i・j の点**：20 units下げました。参照書体の点の位置の範囲内です。
  - 小文字のアクセントは、もともと参照書体より低いので変えていません。
- **括弧など**：( ) [ ] { } | / \ § † などは、記号の中心（340）を基準に上端を843から800へ縮めました。
  - x-height比で1.53になり、Cascadia・Roboto と同程度です。
- **' " ° ™ ¹²³ など**：大文字と同じ比率で下げました。
- **数字**：大文字と同じ高さにそろえました。
  - 4.93の数字は、すべて O のはみ出し（745 / −10）に合わせて描かれていました。1・4・5・7の平らな上端も、Hより8 units高くなっています。
  - 小さいサイズではヒント付けがHの高さへ寄せていましたが、大きいサイズでは数字が大文字より高く見えていました。
  - 5.0では、平らな端や切り口（上端：1 4 5 6 7、下端：1 2 4 7 9）をHの上端・下端（696 / −2）に合わせました。
  - 丸い端（上端：0 2 3 8 9、下端：0 3 5 6 8）は、Oと同じ量だけはみ出します（703 / −9）。
  - どちらの端が平らかは、字形を見て決めた表（`heights.py` の `DIGIT_ENDS`）によります。4.93の輪郭は曲線も折れ線で描いているため、形から自動で判定するとウェイトごとに結果が変わるからです。

縦に縮めると横画が細くなります。縮めた分だけ縦方向にだけ太らせ、横画の太さを保っています。
縦画・字幅・左右の余白は変わりません。

- 横画の太さは、4.93との差が2 unitsか5%以内です（`validation.json` の `strokes_old_new`）。
- 斜体は、傾きを戻してから処理し、10°の傾きを保っています。

見本：`reports/proof-proportions.png`

### 7. 4.93の字形の欠陥を直した

4.93のLight・Medium・SemiBoldと斜体は、輪郭を動かして作った派生です。その過程で、一部の輪郭の向きが逆になっていました。向きが逆の輪郭は、塗るべきところに穴を開けます。（`scripts/mono50/inherited_fixes.py`）

| 字 | スタイル | 4.93の症状 |
|---|---|---|
| Ǻ Ấ Ắ のアキュート | Light・LightItalic・Regular・Medium・MediumItalic | アキュートが白抜き（輪郭線だけ）、半分だけ塗られる、または細い線が欠ける |
| Ą ą Ę Į į ų の ogonek | Light | ogonek が字の脚と重なる部分で切れる |
| Ĩ ẫ ẵ Ẽ Ễ ễ Ỗ Ỡ Ữ のチルダ | SemiBoldItalic（Ẽ Ỗ ỗ は LightItalic も） | チルダの中に小さな白い切れ込み |
| Ђ（U+0402） | Light | ボウルの内側が斜めの線で閉じ、カウンターが塗りつぶされる |
| ℮（U+212E） | Light・LightItalic | 輪郭がばらばらで、字の下半分などが欠ける |

- 逆向きの輪郭は、名前ではなく形で探しました。
  - 正規のカウンターは、ほかの輪郭のインクの内側にあり、囲む輪郭から線の太さ分離れています。
  - 欠陥は、インクからはみ出しているか（ogonek）、囲む輪郭に沿って走っています（アキュートの二重輪郭、チルダの小さな輪）。
  - はみ出しているものは向きを直し、内側にあるものは削除しました。どちらもほかの点は動きません。
  - 交差する画が囲む正規の三角の空き（Ҟ の横棒の下、↚ ↛）は、全ウェイトを目で確認したうえで除外しています。
- Light の Ђ：ボウルの内側の弧が、往復する別の輪郭として残っていました。この弧を本体の輪郭に戻しました。
- ℮：細い線を含む字で、細らせるとその線が消えます。ウェイトによる差もほとんどありません（インク面積は Regular 57,852、Medium 58,696）。そこで、Light には Regular、LightItalic には Italic の輪郭を使いました。

## 互換性

- **Friday Mono JP・Friday Mono Plain JPは5.0では作っていません。**
  - 日本語は、アプリの代替フォントで表示されます。
  - 日本語も同じ書体で表示したい場合は、4.93のJPを使い続けられます（[Releases](https://github.com/Crowlxy/FridayFonts/releases/tag/mono-v4.93)）。
- **0の斜線を消したい場合**は、OpenTypeの`ss01`または`cv01`を使います。Plain版はありません。
  - VS Codeの例：`"editor.fontLigatures": "'ss01'"`
- 行の高さは4.93と同じ1.28emです。文字の位置は、行の中で88 units下がります。
- IBM i ACS用には、5.0ではなく比較用の `Mono ACS Study` を使います（`comparisons/mono-acs-study/`、行の高さ1.000em）。

## 検証

`reports/` に結果があります。

- **`validation.json`**（`scripts/mono50/verify_mono_50.py`）。全10スタイルで失敗0です。
  - 文字セットが `coverage.json` と一致する
  - 字幅が0か600だけ
  - 外接矩形と字幅が4.93から変わっていない（罫線、▲▼、高さを変えた字、欠陥を直した字を除く）
  - キャップ高・小文字の上端が目標どおりで、x-heightが変わっていない。ł と l の上端がそろう
  - 数字の平らな端がHの上端・下端に、丸い端がOの上端・下端に、±1 unitで一致する
  - 向きが逆の輪郭が残っていない。Ђ と ℮ の輪郭の数が Regular / Italic と同じ
  - 横画の太さが4.93から2 unitsか5%以内
  - 折れ線の端が0
  - 丸い字と平らな字の高さ差が0px（9〜32px）
  - 数字の高さがそろう（9〜24px）
  - 全字を8サイズで描画して、エラー・空白が0
  - 罫線のすき間が0。縦の罫線が8〜50pxでセルの高さいっぱいに描かれる
  - 行の数値と、二重下線68条件
  - 名前・太さ・斜体の設定
  - HarfBuzzで、分解表記384組がすべて1セルにまとまり、ゼロが`ss01` / `cv01`で切り替わる
  - WOFF2の輪郭・命令・テーブルがTTFと一致する
- **`outline-compare.json`**（`scripts/mono50/compare_outlines.py`）。高さを変えていない字（406〜409字）について、4.93と5.0の輪郭を面積の差で比べました。10スタイルすべてで1%未満です。
- **`spike-check.json`**（`scripts/mono50/spike_check.py`）。輪郭に細い針状のとげがないかを調べました。
  - 新たに見つかったものは、新旧を重ねて目で確認しました。
  - 確認した結果は、どれももとの設計どおりの鋭い角です（{ } の先端、A の内側の頂点など）。
  - 確認していないものは0件です。
- **`gdi-heights.json`**・**`gdi/`**（`scripts/mono50/windows/`）。フォントはインストールせず、プライベート読み込みで測りました。
  - Windows GDIでの丸い字の高さ：10スタイルとも、9〜32pxでずれ0
  - 全1,251字形×13サイズ（各16,263件）の描画エラー：0
  - 行の高さ：12pxで16px（全ウェイト同じ）
- **見本画像**：`proof-round-letters.png`、`proof-line-box.png`、`proof-styles.png`、`proof-proportions.png`

見本画像はFreeTypeの描画で、アプリのスクリーンショットではありません。

## 残る事項

- **アプリでの目視確認はまだです。**
  - Windows Terminal・VS Code・ブラウザで表示した確認はしていません。
  - macOSでの表示も確認していません。
  - GDIの数値とFreeTypeでの検査は済んでいます。
- **Light・SemiBoldの欧文は、Iosevka本来のウェイトではありません。** 4.93と同じく、Regular・Mediumの輪郭を細らせ・太らせて作っています。
- **SemiBold・SemiBoldItalic の数字**は、ttfautohint の初回結果で一部のサイズの高さが1pxずれます。ヒント付けの制御ファイル（`scripts/rehint.py`）で補正し、9〜24pxでそろうことを確認しています。

## 再生成

`FridayFonts/` で次を実行します。

```sh
py scripts/mono50/coverage_votes.py <4.93の FridayMono-Regular.ttf>   # 収録文字の票決（coverage.json）
py scripts/mono50/build_mono_50.py                                  # work/mono-5.0/ に出力
py scripts/mono50/verify_mono_50.py
py scripts/mono50/compare_outlines.py
py scripts/mono50/spike_check.py
py scripts/mono50/proof_mono_50.py
pwsh scripts/mono50/windows/gdi_heights.ps1 -Dir work/mono-5.0/ttf -Out work/mono-5.0/reports/gdi-heights.json
pwsh scripts/mono50/windows/gdi_all_glyphs.ps1 -Dir work/mono-5.0/ttf -Out work/mono-5.0/reports/gdi
py scripts/mono50/package_mono_50.py                                # releases/mono-5.0/ と FridayMono-5.0.zip
```

必要なもの：

- `FridayMono-4.93.zip`（正規配布。マニフェストのSHA-256で照合します）
- Python 3.12：fontTools、ttfautohint-py、skia-pathops、uharfbuzz、Pillow、brotli
- `coverage_votes.py` を実行する場合は、比較した6書体

フォントの利用・再配布の条件は、同梱の`OFL.txt`と`licenses/`を参照してください。
