# Friday Mono 5.0.2 / 2026-10-09

5.0.1 の修正版です。**Light の ½（U+00BD）が壊れていた問題**を直しました。ほかの字形・字幅・ヒント・行の値は 5.0.1 と同じです（変わった字形は Light の ½ 1字だけで、他の9スタイルは全字形の座標と送り幅が 5.0.1 と一致します）。5.0 の説明は [releases/mono-5.0/README.md](../mono-5.0/README.md)、5.0.1 は [releases/mono-5.0.1/README.md](../mono-5.0.1/README.md) にあります。

> この版は**まだ公開していません**（GitHub Release は mono-v5.0.1 が最新）。公開するかどうかは別に決めます。

## 5.0.1 からの変更

### Light の ½ の分母が壊れていた

- 症状：Light だけ、½ の分母の 2 が小さな「∠」のような断片になっていました。12〜150 px のどの大きさでも同じです。他の4ウェイトと Italic 系は正常でした。
- 原因：4.93 の Light から引き継いだ輪郭の欠陥です。分母の輪郭が 13 点しかなく、2 の形を成していませんでした。ヒントではなく輪郭の問題なので、5.0 でも 5.0.1 でも同じ壊れ方でした。
- 修正（`scripts/mono50/inherited_fixes.py` の `rebuild_light_half`）：Light の数字 2 を、½ の分母の枠に収まるように拡縮して置き直しました。枠は、壊れた輪郭の左右と下端、Light の ¼ の分母の上端に、Regular が ½ と ¼ の間で持つ差を足したものです。同じ作りの ¼・¾・⅓ と並べて、大きさと線の太さが揃うことを目で確認しました。分母の点数が Regular の 3 分の 1 未満のときだけ働くので、直った入力には何もしません。
- 版：内部バージョンを 5.002 にしました。

### 検査の追加

- **隣り合うウェイトの比較**（`scripts/mono50/weight_ladder.py`、`verify_mono_50.py` から呼びます）：4.93 や 5.0 の自分自身との比較では、入力が壊れていると一致して合格してしまいます。そこで、直立5ウェイトを 160 px/em で描き、隣り合うウェイトの間で「軽い方のインクが重い方の 4 px 以内にあるか、逆もそうか」を調べます。4 px より離れたインクのかたまりの最大が 100 px を超える字があれば失敗にします。
- 5.0.1 に当てると U+00BD が 476 px で失敗します（他は 16 px 以下）。5.0.2 の最大は 16 px（U+00BF・U+00A1）で、失敗 0 です。
- Italic 系は対象外です。Regular と Medium の間で、ギリシャ文字・キリル文字の大文字（Δ・Λ・А など）が 4 px 以上動くため、同じ検査では意図した違いと区別できません。目で見ると崩れではなく、字形の傾きと幅の違いです。
- `package_mono_50.py` が書く `SHA256SUMS.txt` の改行を LF にしました（5.0.1 までは Windows で CRLF になっていました）。

## 検査結果

- `verify_mono_50.py`：失敗 0（1,062字。輪郭の折れ 0、罫線のすき間 0、丸い字と平らな字の高さ差 0、数字の高さ、二重下線、シェーピング、WOFF2、隣のウェイトとの比較）
- `compare_outlines.py`：4.93 との面積差が 1 % を超える字は 0（10スタイル）
- `spike_check.py`：未確認のとげは 0
- Windows GDI（複製を使い、`GetFontData` で描画中のバイト列の一致を確認）：丸い字と平らな字の高さ差 0、全字形の描画 16,263 ケース × 10スタイル、エラー 0
- 5.0.1 との比較：Light の `onehalf` だけが変わり、他は全字形が同一（グリフ順・cmap も同一）。

未確認：アプリ上の ClearType での目視確認、macOS。
