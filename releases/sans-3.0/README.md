# Friday Sans 3.0 / Friday Sans UI 3.0

2.5 を「Windows や小さいサイズで硬く見える」点から作り直した版です。文字セットと字形の骨格は 2.5 と同じです。角を丸め、線をわずかに太らせ、ヒントを外しました。Sans UI は字面を約 4 % 大きくし（字幅も同じ比率）、en/em スペース（U+2000〜2003）の幅も直しています。

| ファミリー | ウェイト | 用途 |
|---|---|---|
| Friday Sans | Light / Regular / Medium / SemiBold / Bold | 本文 |
| Friday Sans UI | Light / Regular / Medium / SemiBold / Bold | 画面の文字。かなと約物の幅を詰めた版 |

計10 TTF、全字形の WOFF2 が10、Web 用の軽量 WOFF2 が10。内部バージョンは Version 3.001 です。

## 何が変わったか

### 1. 硬さを取った（Windows・小サイズ）

2.5 は Windows 向けにヒントを付けていました（欧文は ttfautohint、かな・漢字は Chlorophytum）。ヒントは線を1画素の行に吸着させるため、Windows の GDI・WPF・DirectWrite では小さい字がくっきり硬く出ます。ヒントを外すだけなら Mac と同じ柔らかさになりますが、線が細く灰色に見えます。そこで 3.0 は次の3つを組み合わせました。

1. **角を丸めた。** 尖った角（凸）に短い2次曲線の面取りを入れます。切り込む長さは線幅の 0.19 倍（凹の角は 0.09 倍）です。Regular で凸 12 units・凹 6 units。線の先端の鋭さは残るので、払いが痩せたり短くなったりしません。
2. **線をわずかに太らせた。** 輪郭を外へ 線幅の約 3.9 %（片側）オフセットします。Regular で片側 2.5 units、両側で線幅 +5 units（約 +8 %）。Mac が文字を少し太らせて描くのと同じ濃さを、Windows でも得るためです。画と画の隙間が閉じる字は、輪郭数と面積の増え方を見て、片側の量を二分探索で減らしています（Regular で約 1,700 字が減量対象。減量の量は `reports/build-log.json` に字ごとに記録）。 **画数の多い漢字ほど太らせを減らします。** 同じ量を全字に足すと、もともと線も隙間も細い画数の多い字（鬱・龍・議・響 など）だけが黒くなるためです。その字のインク面積を、同じ書体の漢字の中央値で割った比 r で決め、r ≤ 1.00 は全量、r = 1.15 以上は 15 %、その間は直線で減らします（JIS 第一水準 3,059 字のうち Regular で 1,130 字＝37 % が減量対象、うち 401 字が半分未満）。
3. **ヒントを全部外した。** `fpgm`・`prep`・`cvt `・各字形の命令を削除し、`gasp` は全サイズ「グレースケール＋ClearType 平滑」のみ（グリッドフィットなし）にしました。

| 片側の太らせ量（1000 units 換算） | Light | Regular | Medium | SemiBold | Bold |
|---|---:|---:|---:|---:|---:|
| 太らせ | 1.9 | 2.5 | 3.1 | 3.4 | 3.9 |
| 凸の角の面取り | 9.3 | 12.2 | 14.9 | 16.5 | 19.0 |

### 2. Sans UI を大きくした

2.5 の Sans UI は、字面が em の 0.850（漢字の高さ）でした。Yu Gothic UI は 0.875、Meiryo UI は 0.870、Noto Sans JP は 0.880 です。UI が小さく感じる原因はこれです。3.0 は同じ輪郭を em 1010 として読み直し、字面を **0.887** にしました（Friday Sans は 0.896）。

| 漢字の高さ / em | Friday Sans UI 2.5 | **Friday Sans UI 3.0** | Yu Gothic UI | Meiryo UI | Noto Sans JP | Friday Sans 3.0 |
|---|---:|---:|---:|---:|---:|---:|
| 漢字の高さ | 0.850 | **0.887** | 0.875 | 0.870 | 0.880 | 0.896 |
| x 高さ | 0.518 | **0.541** | 0.500 | 0.552 | 0.527 | 0.546 |
| 大文字の高さ | 0.729 | **0.760** | 0.700 | 0.736 | 0.726 | 0.767 |
| 数字の高さ | 0.739 | **0.771** | 0.712 | 0.750 | 0.739 | 0.778 |

- 欧文・数字は漢字に対する比率を変えていません（x 高さ／漢字の高さ＝0.61、大文字／漢字＝0.86）。この比は Yu Gothic（0.60 / 0.86）、Meiryo UI（0.63 / 0.85）、Noto Sans JP（0.60 / 0.83）の範囲に収まっています。
- 行の高さ（hhea・typo）は、2.5 の 1017 / −253（em 1050）を em 1010 として読み直した値（upem 2000 で 2014 / −501、1.254 em）です。字形に対する行の位置は 2.5 と同じで、Å・Ấ などアクセント付きの大文字は 2.5 と同じ範囲に収まります。em に対する行高は 2.5 の 1.21 em より 3.6 % 大きくなります。GDI が使う Win 値（usWinAscent/Descent）は字形の外接を覆う値のままなので、GDI の自動行間は em に対して 2.5（約 1.77 em）より大きく約 1.85 em になります（RC3 から続く制限）。
- Friday Sans（本文用）の寸法は変えていません。

### 3. 出荷前に見つけて直した問題

| 問題 | 内容 | 対応 |
|---|---|---|
| ベンダー ID が旧名 | `INOR`（Inori Mono 時代）のままだった | `FRDY` |
| Win 行の値がウェイトごとに違う | usWinAscent が 1323〜1328、usWinDescent が 538〜539。GDI で太さの違う字を混ぜると行高がずれる | ファミリー内で最大値にそろえた（全字形の外接を覆うことを確認） |
| 空白の幅が太さで揺れる | U+2000〜2003（en/em quad・en/em space）が Light 1080 … Bold 1135 など、名前の幅と無関係に動いていた | en = 0.5 em、em = 1 em に固定 |
| lsb / tsb | 輪郭が変わるため全字形で再計算 | 実施 |
| Web 用 WOFF2 | 全字形版しかなく 3.2〜3.5 MB／書体だった | JIS X 0208＋欧文＋記号の軽量版（約 1.8〜2.1 MB）を追加 |
| 名前・版 | 説明文・版番号が 2.5 | 3.001（密度対応を入れた版。最初の 3.000 は未公開） |

2.5 のまま残したもの（意図した設計）: 欧文の基線がウェイトで ±12 units ずれる（Hiragino の H の基線を測って写したもの）、x 高さ・大文字の高さがウェイトで増える（太さに合わせた補正）。

## 太らせの量が字ごとに違う件

太らせの量は字ごとに決まります。①画数の多い漢字は密度で減らす（上記）。②その量でも画の隙間や空きが埋まる字は、埋まらない最大量まで二分探索で更に減らす。②で減る字は、Regular で JIS 第一水準 3,059 字のうち 172 字（5.6 %）、Light 83 字、Bold 470 字（15.4 %。濃い画数の多い字）です。かな・ASCII・数字は密度の減量を受けません（かなの r は 0.8 以下）。角の丸めを外した字（`kept_sharp`）は Regular で 206 字、すべて漢字・記号で、かな・欧文はありません。字ごとの量は `reports/build-log.json`（`reduced` が②、`lighter` が①の字数）にあります。

結果として、漢字のインク面積は 2.5 の 1.02〜1.09 倍（Regular・p5〜p95、中央値 1.083）です。画数の少ない字が約 +9 %、多い字は +2〜5 % にとどまり、画数の多い字が相対的に黒くならないようにしています。最も画数の多い上位 10 %（Noto の墨量順）の墨面積は Noto Sans JP 400 の約 0.90、ヒラギノ W3 の約 1.02 倍です。

## ヒントなしの影響の監査（1字ずつ）

ヒントを外した影響を、ヒラギノ角ゴ W3・Noto Sans JP（このPCのもの、wght 400）・Inter（このPCのもの、opsz 14・wght 400）・SF Pro Text で同じ方法で測りました。平均ではなく字ごとの値で比べています（かな・漢字は JIS 第一水準から漢字 600 字、かな全字、欧文 62 字）。生の出力は `reports/audit-unhinted.md`・`reports/audit-unhinted.json`、スクリプトは `scripts/sans30/audit_*.py` です。ヒントなしの描画は、輪郭を 8 倍の超サンプリングで面積どおりにアンチエイリアスして求め、サブピクセル位置 4 通（0 / 0.5 px を縦横）で評価しました。ClearType の平滑フィルタ・ガンマは含まないため、実機の見え方そのものではありません。

**字ごとの濃さ（線の太さ・インク量）**
- 3.0 と 2.5 の字ごとのインク面積比は、漢字 1.021〜1.094（p5〜p95、中央値 1.083）、かな 1.072〜1.084、欧文 1.065〜1.077 です。漢字は画数の多い字ほど小さく（密度に応じた太らせ。上記）、かな・欧文は一定です。**この節の他の数値（線の太さのばらつき、E、位相、高さ）と `reports/audit-unhinted.*` は、密度対応を入れる前のビルドで測ったものです。** 密度対応は画数の多い漢字の太らせだけを減らす変更で、かな・欧文・高さ・メトリクスは変わりません。
- 線の太さの字ごとのばらつき（縦線・横画、級ごとの変動係数）は、ヒラギノ W3・Noto と同程度かそれ以下です（例：漢字の縦線 CV 0.077、W3 0.082、Noto 0.082。±10 % を超える漢字は 599 字中 51 字で、W3 143、Noto 77）。
- ヒラギノ W3 と同じ文字同士のインク面積比は、漢字の中央値 1.083（字ごとの p5〜p95 は 1.031〜1.131）、ひらがな 1.070（0.965〜1.178）、欧文 1.01〜1.04。**かなは字によって差が大きい**ので次の2点を挙げます。これは 2.5 から続く差で（2.5 / W3 も 0.896〜1.085）、ヒント削除の影響ではありません。
  - 小書きのかな（ぃ・っ・ゅ・ぁ・ェ・ゥ・ュ など）は W3 に比べて 10〜16 % 重い。
  - 手描きの ぶ・ふ・ぷ は 12〜15 % 軽い。
- 同じ比を Noto と取るとかなは 0.93〜0.98 と揃っているので、W3 との差は Friday と Noto の違いではなく W3 の設計に由来する部分が大きい。

**ヒントなしの濃さのゆれ（アンチエイリアスの締まり具合 E = ΣC²/ΣC の字ごとの値）**
- E の字による差（p5〜p95 の比）は 12 px で ±5〜6 %、16 px で ±3〜5 % です。W3・Noto・Inter・SF と同じ幅で、**ヒントありの 2.5（FreeType の y 方向ヒント）の E（12 px で 0.546〜0.733）より狭く（3.0 は 0.605〜0.687）なっています**。ヒントは字によってくっきりしたりしなかったりしていたことになります。
- 同じ字を置く位置を変えたときの E のゆれ（4 位相の最大−最小）の平均は、欧文 62 字で 12 px が 0.119（W3 0.106、SF 0.103、Inter 0.097、Noto 0.084）、14 px が 0.068（W3 0.079、SF 0.058、Inter 0.043、Noto 0.042）。**W3・SF と同等、Inter・Noto より 20〜40 % 大きい**です。大きいのは縦線 1 本の字（l・i・j・r・m）で、12 px の最大は l の 0.50（他書体の最大は 0.46）。縦線の太さが約 1 px になるためで、どの書体も同じ字が悪い側に出ます。かな・漢字は 12 px で 95 パーセンタイルが 0.12〜0.21、16 px で 0.08〜0.13 で、Noto・W3 と同じ範囲です。
- ヒントなしだと、同じ字が行の中の位置によって濃くなったり薄くなったりします。Mac と Chrome で今も起きていることで、DirectWrite のサブピクセル位置決めでも同じです。GDI のようにグリフを整数画素に置く環境では位置が揃うため、このゆれは出ません。

**高さ**（em の千分率。12 px で 1 ‰ = 0.012 px）
- 平らな頂部（x 高さ・大文字・数字の 1・4・7 など）は字による差が 0 ‰ で、Noto・Inter・SF と同じです（W3 は 7 ‰）。
- 丸い字のはみ出し（o − x、O − H）は 12 / 11 ‰ で、W3 13 / 15、Noto 14 / 13、Inter 7 / 10、SF 9 / 17 の範囲です。12 px で 0.14 px、16 px で 0.19 px です。
- x 高さは 12 px で 6.55 px のように画素の途中に来ます。2.5 のヒントはこれを 7 px に吸着させていましたが、3.0 は吸着しません（Mac・Noto と同じ）。

**判断**: 字ごとの濃さ・高さは、参照した4書体の範囲内か、より揃っています。外れるのは 12 px 前後の縦線 1 本の字（l・i・j）の位置によるゆれの最大値だけで、他書体の最大より約 1 割大きい程度です。ただし ClearType 実機での確認は別に必要です。

## 残る事項

- **Light に、字形の壊れた漢字があります（Sans・Sans UI とも）。** 共・題は画が欠け、武・昆・廃・戯・魃などに黒い楔が、慮・唄に小さなとげが出ます。目視で確認できたのは 18 字、隣のウェイトとの比較で検出された候補は 75 字です（残りの約 55 字は目視していません）。Regular〜Bold は 0 字です。2.5 から引き継いだ欠陥で、3.0 の処理で生じたものではありません（魃は 2.5 と 3.0 で面積・外接が一致します）。`verify_sans_30.py` は 2.5 と比べるため、2.5 側が壊れていると合格します。詳細と候補の一覧は [reviews/2026-10-09-r3.md](../../reviews/2026-10-09-r3.md)。直るまで、Light で使う漢字は字形を確認してください。
- **公開済みの `sans-v3.0` の資産は、この記録の 3.001 ではありません。** 公開されているのは密度対応前の 3.000（SHA-256 `166493f4…`）で、ここに書いてある 3.001（`d6b537a4…`）は未公開です。
- **Mac と大きいサイズも変わります。** 「Mac・大きいWebなら品質が良い」という評価の側にも、線が（画数の少ない字で）約 8 % 太くなり、角が丸くなり、Sans UI の字面が 4 % 大きくなるという変更が入っています。Chrome（DirectWrite）ではヒントの有無で見た目が変わらなかったため、ラスタ側だけの対処では Chrome・Edge・Electron の硬さが取れず、輪郭を変えました。大きいサイズの変化は小さい（`reports/compare-large-sizes.png`）ですが、2.5 と同じ見た目を求める用途には 2.5 を使い続けてください。

- **Windows 実機の目視確認はまだです。** 比較は GDI+ と Chrome（DirectWrite）での描画で行いました。WPF・WinUI・Office・Edge の各アプリでの見え方、特に Light / SemiBold は未確認です。
- **ヒントがないので、小さいサイズでは画素の位相で線の濃さがわずかにばらつきます**（1 画素行に吸着しないため）。これは Mac と同じ描き方で、2.5 の「くっきり」を手放した代わりの性質です。「くっきり」が必要なら 2.5 を使い続けてください（書体名は同じなので、入れ替えると後から入れた方が使われます）。
- 輪郭数が 2.5 と変わる字（Regular で 瀬 U+7027・臘 U+81D8 など、書体ごとに 1〜5 字）は、元の輪郭にほとんど幅のない接点・1 unit 以下の点があり、座標の丸めで離れる／消えるためです。面積と外観は変わっていません。
- 手描きかなは、2.5 と同じく、新ウェイトを含めユーザーの目視承認を受けていません。角の面取りと太らせは手描きかなにも同じ規則で掛けています。
- RC3 の制限（旧 GDI の自動行間が広い、Win 値が全字形を覆うための約 1.87 em）は引き続き全ウェイトに共通です。
- TTF は 2.5 の約 1.3 倍（10〜11.8 MB／書体）です。upem を 1000 から 2000 にして、0.5 unit 刻みの太らせを丸めずに保つためです。

## 再生成

2.5 の配布 ZIP（`sans-v2.5`）を入力にします。ソースの Inter・Noto Sans CJK JP は使いません。`FridayFonts/` で：

```sh
mkdir -p work/sans-3.0/x && gh release download sans-v2.5 --repo Crowlxy/FridayFonts -D work/sans-3.0/in
# FridaySans-2.5.zip を work/sans-3.0/x に展開
```
