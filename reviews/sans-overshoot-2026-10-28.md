# Sans 3.1.0: 丸い字のオーバーシュートがウェイトで違う（課題 #22）

2026-10-28 に、Friday Sans / Sans UI 3.1.0 の全10書体で測定した結果です。以下の「測定」「見え方」は、**直す前**（足だけを0にそろえた状態）の値です。原因と、直した結果は末尾の「原因」「修正」にあります。

## 測定（UPM 2000、単位は units）

平らな字（H・x）の高さを 0 とし、丸い字（O C G / o c e s / 0 8）が上下にはみ出す量です。`FridaySans` と `FridaySansUI` で値はほぼ同じです。

| ウェイト | 下側（基準線の下） | 上側（大文字の高さの上） | 大文字の高さに対する下側 |
|---|---|---|---|
| Light | −2 | +20 | 0.13 % |
| Regular | −15 | +22 | 0.98 % |
| Medium | −30 | +24 | 1.94 % |
| SemiBold | −41（小文字は −43） | +24 | 2.63 % |
| Bold | −56（小文字は −58） | +24 | 3.58 % |

- 上側は全ウェイトでほぼ一定（+20〜+24）です。
- 下側だけが −2 から −56 まで大きく増えるので、Bold では下が上の約2.4倍になり、上下が非対称です。
- 一般には、オーバーシュートは上下で同程度か、太いほうが小さくなります。

## 見え方（目視）

見本: `sans-overshoot-2026-10-28.png`（120 px、灰色の線が基準線。上から Light・Regular・Bold）。

- 14〜24 px では、どのウェイトでも差は識別できませんでした。
- 120 px の Bold では、O・C・e・o・s の下が基準線の下に出ているのが分かります（約7 px）。Light は線にほぼ接しています。
- 実機（ClearType など）での見え方は確認していません。

## 案

| 案 | 内容 |
|---|---|
| A | 現状維持。次の版以降も触らない |
| B | 外れ値だけ補正。Medium〜Bold の下側を Regular 付近（約1 %）、または上側と同程度（+22 前後）に寄せる |
| C | 全ウェイトで上下を同じ比率に統一 |

B・C は、丸字の最下点・最上点とそのハンドルを動かす輪郭の再設計です。対象は ASCII・Latin 拡張・数字・アクセント付き字形・`ss01`〜`ss08` などで、各書体で数百グリフになります。線の太さの均一さと曲線のつながりを崩しやすいため、全ウェイトで検証と目視をやり直す必要があります。

## 原因

3.002 の TTF（直す前の入力）で、平らな字（H・x）と丸い字の下端を測りました。

| ウェイト | H・x の足 | O・o の下端 | 差（丸字 − 足） |
|---|---|---|---|
| Light | +18 | −2 | −20 |
| Regular | +7 | −15 | −22 |
| Medium | −6 | −30 | −24 |
| SemiBold | −17 | −41 | −24 |
| Bold | −32 | −56 | −24 |

- 3.002 では、足そのものが基準線から浮き沈みしていました（Light は上に18、Bold は下に32）。これは `build_sans_30.py` の太らせ（輪郭を外へ広げる）で、ウェイトが太いほど字全体が下へ伸びたためです。
- 丸字は足の約20〜24 units 下で、全ウェイトに共通でした。つまり**設計どおりのオーバーシュートはそろっていました**。
- 3.1.0 の `align_baseline.py` が足だけを基準線 0 に動かし、丸字を動かさなかったため、足の移動量（Light −18 … Bold +32）の分だけ丸字との関係がずれました。ウェイトでばらついたのは、この整列の副作用です。

## 修正

`scripts/sans30/align_overshoot.py` を追加し、丸字の下側を足と同じ量だけ動かして 3.002 の関係を戻しました。

- 対象は、高さが 1050 units 以上の欧文・数字で、基準線付近（−100〜+12）に水平な接線をもつ丸い下端がある字形と、その GSUB の置換先（`ss01` など）です。丸付き字形と、`subs`・`dnom` の小さい数字は除きます。
- y だけを動かします。基準線から200 units までは全量、600 units で0になるよう滑らかに減らします。内側の輪郭も同じ量動くので、下の線の太さは変わりません（例：Bold の `o` で外−58／内158 → 外−26／内190、どちらも差216）。上側・字幅・輪郭点の数は変わりません。
- 足の点は動かしません。`t` の曲線の足も同じ処理を受けます。

結果（`O C G S U o c e s 0 3 5 6 8`、全10書体）：下端は −14〜−28 units。Light −20 前後、Regular −22、Medium〜Bold −24〜−26 です。`t` は Light・Regular が 0、Medium〜Bold が 0〜−4 で、ウェイトの違いはなくなりました。見本は 120 px の Bold・Light で、直す前後を並べて確認しました。

## 残っていること

- 実機（ClearType など）での見え方は未確認です。
- Greek・Cyrillic の丸字と平らな字は、3.1.0 の整列の対象外のままです（3.002 と同じ浮き沈み）。Latin と混ぜると、Bold で約30 units（0.03 em）ずれます。
- 下付き記号（アクセント）の位置を決める GPOS のアンカーは動かしていません。丸字の下端が最大32 units 動いた分、下付き記号との間隔が変わります。見本では問題なく見えました。
