# Sans 3.1.0: 丸い字のオーバーシュートがウェイトで違う（課題 #22）

2026-10-28 に、Friday Sans / Sans UI 3.1.0 の全10書体で測定した結果です。3.1.0 では直していません。3.002 から同じ値で、3.1.0 の変更（平らな足を基準線 0 にそろえる）は丸い字を動かしていません。

## 測定（UPM 2000、単位は units）

平らな字（H・x）の高さを 0 とし、丸い字（O C G / o c e s / 0 8）が上下にはみ出す量です。`FridaySans` と `FridaySansUI` で値はほぼ同じです。

| ウェイト | 下側（基準線の下） | 上側（大文字の高さの上） | 大文字の高さに対する下側 |
|---|---|---|---|
| Light | −2 | +20 | 0.13 % |
| Regular | −15 | +22 | 0.98 % |
| Medium | −30 | +24 | 1.94 % |
| SemiBold | −41（小文字は −43） | +24 | 2.63 % |
| Bold | −56（小文字は −58） | +24 | 3.58 % |

- 上側は全ウェイトでほぼ一定（+20〜+24）です。
- 下側だけが −2 から −56 まで大きく増えるので、Bold では下が上の約2.4倍になり、上下が非対称です。
- 一般には、オーバーシュートは上下で同程度か、太いほうが小さくなります。元の Inter や Noto からの補間の結果か、太らせる工程（`build_sans_30.py` の輪郭オフセット）の副作用か、意図した設計かは未確認です。

## 見え方（目視）

見本: `sans-overshoot-2026-10-28.png`（120 px、灰色の線が基準線。上から Light・Regular・Bold）。

- 14〜24 px では、どのウェイトでも差は識別できませんでした。
- 120 px の Bold では、O・C・e・o・s の下が基準線の下に出ているのが分かります（約7 px）。Light は線にほぼ接しています。
- 実機（ClearType など）での見え方は確認していません。

## 案

| 案 | 内容 |
|---|---|
| A | 現状維持。次の版以降も触らない |
| B | 外れ値だけ補正。Medium〜Bold の下側を Regular 付近（約1 %）、または上側と同程度（+22 前後）に寄せる |
| C | 全ウェイトで上下を同じ比率に統一 |

B・C は、丸字の最下点・最上点とそのハンドルを動かす輪郭の再設計です。対象は ASCII・Latin 拡張・数字・アクセント付き字形・`ss01`〜`ss08` などで、各書体で数百グリフになります。線の太さの均一さと曲線のつながりを崩しやすいため、全ウェイトで検証と目視をやり直す必要があります。

## 次にやること（着手する前）

1. 原因の特定: `build_sans_30.py` の途中（太らせる前後）で下側がどう変わるかを測る。2.5 の値も見る。
2. 実機確認: Windows・Mac で 48 px 以上の Bold・SemiBold の丸字を並べて、基準線の沈みが気になるか判断する。
3. 気になる場合だけ案 B から着手する。やるなら次の版（3.2 以降）とし、3.1.0 には入れない。
